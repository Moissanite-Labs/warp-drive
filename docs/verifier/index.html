Verifier

Four checks. Each one can stop the load.

This page states what each stage proves, what it does not prove, and the exact command that runs its tests offline.

Exact: 9 canaries, test counts with runnerDocumented: stage behaviourUnverified live: Cerebras, llama timings
01 // Stage 1Documented · fingerprint.py

Stage 1: fingerprints, before any model call.

Warp computes five digests: layout, GGUF file, config with tokenizer and chat template, Plane1 lineage with zero contested heads, and runtime flags. An optional zone manifest pin can stop the load with ERR_ZONE_MANIFEST_DRIFT. Any mismatch fails closed, before GPU or HTTP work starts.

Does not prove the checkpoint is good. It proves the checkpoint is the one you pinned.

Stage 2: exact numbers, no division.

Warp checks adapter bounds with exact integers: value times limit_den is at most limit_num times radix_scale. The docs state under one millisecond on CPU. This was not measured for this site. Source file: certificate.py.

Does not prove the adapter is good. It proves the stated bounds hold under exact arithmetic.

Stage 3: canaries in shadow.

Warp loads the adapter at scale 0.0 and runs verifier-owned canaries only. The schema file holds 9 canaries. That count is exact. The README live run mentions 5 canaries with no artifact in the repo, so this site keeps the two numbers separate and trusts the file count. Source files: canary.py and llama_client.py.

Does not prove general behaviour. It proves the canary set still passes in shadow.

02 // Stage 4Documented · ledger.py

Stage 4: record, kill switch, rollback.

The kill switch scales the adapter to 0.0. Warp then erases slots across three banks: kv_cache, ssm_recurrent and lattice_horizontal_streams. A failed flush quarantines the slot with ERR_LATTICE_FLUSH_FAILED. Every mount, reject and rollback lands in a hash-chained HMAC JSONL ledger served over a Unix socket. Source files: ledger.py, verifier.py and server.py.

Does not prove the model forgot everything. It proves warp ran its erase steps and signed the record.

Two controller orders. Do not merge them.

unittest alone misses two pytest files. Counts: pytest 271 passed and 2 skipped. unittest 154 ran and 2 skipped. Opt-in live tests need WARP_LIVE_LLAMA_TEST or WARP_LIVE_CEREBRAS_TEST plus credentials or model files. Live status is unverified.

Schemas in the repo: adapter bundle, Cerebras candidate (provisional, pending a lane freeze), and the canary suite. The modeld config file is an example, not a schema.

Cerebras, stated plainly

The client targets a Kimi model id on Cerebras. Live status is unverified. Only mocked contract tests pass: 48 tests in tests/test_cerebras_client.py, counted from source. A dedicated endpoint may be required. This site makes no live Cerebras speed claim.
