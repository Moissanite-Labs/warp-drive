Architecture

Where warp sits, and what it trusts.

Warp is Layer 3 of a five-layer stack described in the README. It sits between the agent loop above it and the model server below it, and it trusts neither side without checks.

Exact: 14 modules, 7389 linesDocumented: stack and trust pathPlanned: machines and boot

The five-layer stack, as the README states it.

03 // Machines and imagesPlanned: PLAN.md

Three machines. None has booted warp yet.

State banks are named kv_cache, ssm_recurrent and lattice_horizontal_streams. The first two map to real model state. The lattice bank is simulated only. No real lattice backend has run.

The plan names three machines and three mkosi profiles: vmtest, compute-rtx3080 and client-omarchy, with btrfs subvolumes and single-reboot recovery. Every hardware and boot line in that plan is future work. Treat it as a plan, not a result.
